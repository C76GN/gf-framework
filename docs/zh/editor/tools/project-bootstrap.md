# 最小项目向导

在 GF Workspace 打开 **GF Project Bootstrap / 最小项目**，可以生成一份只依赖 kernel 的可运行示例。它包含 Model、System、Installer、启动场景和可见的计数按钮。

## 创建与运行

1. 启用 GF 插件，确认 `Gf` AutoLoad 指向 GF 的入口脚本（或其有效 UID），并启用单例。同名的其他脚本不会被向导采用或改写。
2. 采用默认目录 `res://game/bootstrap` 和类名前缀 `GameDemo`，或改成项目需要的名称。
3. 点击 **预览创建计划**，检查六个新文件、将追加的 Installer，以及主场景处理方式。
4. 点击 **创建最小项目**。工具保存文件和当前项目设置，并打开样例场景。
5. 按 **F6** 运行当前场景，看到“GF 已就绪 · 计数：0”后点击 **计数 +1**。

默认保留主场景。只有勾选 **创建后将样例设为项目主场景** 才替换 `application/run/main_scene`；原有 `gf/project/installers` 保留顺序，并追加新 Installer。

## 生成内容

| 文件 | 职责 |
|---|---|
| `counter_model.gd` | 保存计数，发送变化信号 |
| `counter_system.gd` | 声明 Model 依赖，处理递增请求 |
| `game_installer.gd` | 装配模块，检查异步注册结果与取消状态 |
| `bootstrap.gd` | 等待 `Gf.init()`，连接 UI，退出场景时解除订阅 |
| `bootstrap.tscn` | 展示状态文本和计数按钮 |
| `README.md` | 保存这份示例的实际路径与使用说明 |

生成后这些文件属于项目，可以直接修改。工具不覆盖已有文件、不替换已有 Installer，也不自动重构项目目录。输出不能位于 `addons` 或 `.godot`；类名前缀只接受英文字母开头的字母、数字与下划线，最多 48 个字符，并检查已登记的全局类型冲突。

创建后导入尚未完成时，工具临时保留生成的类名；导入完成后由 Godot 的实际全局类登记决定冲突。以后修改或移除 `class_name`，不需要重载插件即可复用已经释放的类名。

## 失败与恢复

创建操作会保存当前项目设置，不进入场景 Undo / Redo。预览后项目设置或磁盘配置改变，需要重新预览。

工作区刷新、页面卸载或宿主上下文撤销会使旧预览失效，旧按钮不会继续创建文件。已经开始的同步提交会完成保存或补偿；页面消失不会中断文件事务。

文件先通过有界事务创建，再保存 Installer 与显式选择的主场景设置。设置保存失败且磁盘配置仍保持原值时，工具恢复本次设置并移除内容仍匹配的新文件；可能留下空目录。文件或设置已被其他操作改动时，工具保留它们并明确报告需要检查的路径，避免删除未知改动。

遇到 **需要检查并恢复** 时，页面保留恢复说明并锁定创建输入。先检查 `project.godot`、Installer 列表和报告中的文件；完成手工核对与恢复后，使用 **工具 > GF > 刷新 GF 编辑器贡献** 重建页面，或重新加载插件后再创建。仅关闭再打开 Workspace 会保留原页面。多个文件与项目设置不是崩溃原子提交；进程中断后也应核对这些内容。

示例只演示 kernel 装配与场景接入。输入、存档、玩法及其他扩展仍由项目按需添加。已有完整项目可以保留原场景和 Installer，只把这份示例作为可运行的参考。
