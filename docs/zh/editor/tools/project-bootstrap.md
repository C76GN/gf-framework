# 项目初始化

在 GF Workspace 首页选择 **初始化项目**，或打开 **GF 项目初始化 / 项目初始化** 页面，可以建立空项目的启动入口，也可以为现有项目准备接入内容。生成代码只依赖 kernel，不包含玩法示例。

## 初始化新项目

1. 启用 GF 插件，确认 `Gf` AutoLoad 指向 GF 的入口脚本（或其有效 UID），并启用单例。同名的其他脚本不会被向导采用或改写。
2. 保持 **初始化新项目** 模式，采用默认目录 `res://app`，或选择项目自己的入口目录。
3. 查看自动更新的变更摘要。默认新建下表四个文件，将 Boot 设为项目主场景，并登记空的项目 Installer；**高级选项**可以关闭 Installer 或添加 README。
4. 点击 **初始化项目**。工具按摘要创建文件；新项目模式会更新主场景等设置、保存当前项目设置，并打开 Boot。
5. 按 **F6** 运行 Boot，确认初始化成功后进入空 Main；之后在 Main 中开始制作项目内容。

| 文件 | 职责 |
|---|---|
| `boot.gd` | 等待 `Gf.init()`，处理初始化失败，在成功后进入 Main |
| `boot.tscn` | 项目启动场景 |
| `main.tscn` | 项目自己的空主场景 |
| `project_installer.gd` | 可选的空装配入口，默认创建并追加到 `gf/project/installers` |
| `README.md` | 可选的初始化说明，默认不创建 |

生成脚本不声明全局 `class_name`，无需类名前缀。关闭 Installer 后仅生成三个启动文件；没有待注册模块时，空 Installer 不是运行的前提。

已有主场景或非空 Installer 列表时，新项目模式会拒绝创建。请明确切换到 **接入现有项目**，不要为了使用向导先删除已有设置。

## 接入现有项目

此模式保留原有主场景和 Installer 顺序，不创建 Boot 或 Main，也不改写已有业务脚本。

1. 选择 **接入现有项目**，指定新文件的输出目录。
2. 在 **高级选项**中选择是否创建新的空 Installer，以及是否添加 README。已有 Installer 不会被替换；新 Installer 只在选择创建时追加。
3. 确认变更摘要并执行。创建 Installer 会追加登记并保存当前项目设置；单独创建 README 不保存项目设置。使用 **复制接入片段**，将实际初始化代码放到项目自己选定的启动入口。
4. 根据需要使用 **打开 Main** 和 **打开 Installer** 继续编辑。

两项高级选项都关闭时，页面只提供接入说明：**初始化项目**按钮不可用，复制片段和打开已有主场景仍可使用，不写文件或保存项目设置。向导不会判断项目已有脚本是否调用了 `Gf.init()`；请先核对现有启动流程，再决定片段的接入位置。

## 文件与能力的归属

生成后的入口、场景和 Installer 都属于项目，可以自由修改。GF 升级不会重新套用模板或覆盖这些文件，初始化工具也不负责后续同步。重复生成遇到已有目标文件会拒绝覆盖。

`res://app` 只是入口目录的默认建议。工具不批量创建空目录，不要求项目采用特定 Project Layout profile，也不默认创建 Model、System、日志、输入、存档或环境文件。需要注册模块时，使用[菜单与脚本模板](../menus-templates.md)创建相应脚本，再写入项目 Installer；需要访问器时，再通过已有生成入口生成。可选扩展由项目显式启用。

输出不能位于 `addons` 或 `.godot`。旧版本生成的计数示例已经属于项目，工具不会自动删除；如不再使用，请先移除相应主场景、Installer 和代码引用，再由项目自行清理文件。

## 变更摘要与失败恢复

打开页面、切换模式和编辑选项只会刷新只读摘要。点击 **刷新变更摘要** 可以重新检查磁盘与项目设置；点击 **初始化项目** 才会写入。摘要生成后项目设置或磁盘配置改变，必须重新检查，旧计划不能直接提交。

仅在本次计划包含设置变更时，创建操作才会保存当前项目设置；单独创建 README 不保存设置。创建不进入场景 Undo / Redo。工作区刷新、页面卸载或宿主上下文撤销会使旧计划失效，旧按钮不会继续创建文件。已经开始的同步提交会完成保存或补偿；页面消失不会中断文件事务。

文件先通过有界事务创建；有设置变更时，再保存当前项目设置。设置保存失败且磁盘配置仍保持原值时，工具恢复本次设置并移除内容仍匹配的新文件；可能留下空目录。文件或设置已被其他操作改动时，工具保留它们，并报告需要检查的路径。

遇到 **需要检查并恢复** 时，页面保留恢复说明并锁定创建输入。先检查 `project.godot`、Installer 列表和报告中的文件；完成手工核对与恢复后，使用 **工具 > GF > 刷新 GF 编辑器贡献** 重建页面，或重新加载插件后再创建。仅关闭再打开 Workspace 会保留原页面。多个文件与项目设置不是崩溃原子提交；进程中断后也应核对这些内容。
