# Scene Groups 场景组查询

`gf.tool.scene_groups` 是制作期工具包，用于回答“这个 Group 在哪些场景的哪些节点上声明”。`GF Scene Groups` 页面读取已保存的 `.tscn` / `.scn`，建立组名、声明场景和节点路径的查询结果。它适合查找组名拼写、定位待修改声明，以及确认一个场景的组来自自身还是被引用的场景。

## 第一次使用

1. 启用 GF 编辑器插件，从 `工具 > GF > 打开 GF 工作区` 打开 [GF Workspace](../workspace.md)。
2. 选择简称为“组查询”的 `GF Scene Groups` 页面。
3. 保存需要检查的场景，再主动启动扫描。页面打开时保持空闲。
4. 输入组名、场景路径或节点路径筛选结果，使用分页查看匹配项。
5. 从结果打开声明场景并定位节点，在 Godot 场景编辑器中查看或修改 Group。

工具显示的是扫描时读取到的已保存声明。编辑器里的未保存修改、游戏运行时调用 `add_to_group()` 加入的成员，以及当前远程场景树不属于结果。修改并保存场景后，需要重新扫描才能更新查询。

扫描根只接受规范的 `res://` 目录或其子目录。隐藏子目录及 `.gdignore` 排除的目录不参与场景发现，因此结果也不包含这些范围；遇到链接或无法读取的路径时会报告问题并标记结果不完整。范围约定与预算应和结果一起理解。

## 声明来源怎么理解

每条结果对应一个场景自己保存的 Group 声明，包含组名、声明场景路径和节点路径。场景继承或嵌套实例带来的既有声明保留在来源场景，不会在每个引用场景里再列一遍；引用场景自己追加的声明仍然显示。

例如，`player.tscn` 的根节点声明了 `actors`，`level.tscn` 实例化这个玩家：查询 `actors` 会指向 `player.tscn` 的声明。如果 `level.tscn` 又为这个实例追加 `interactable`，该条结果会指向 `level.tscn` 中的实例节点。继承场景采用相同规则。

因此，查询结果可用来定位需要编辑的来源，不能直接推导某个关卡运行后会有多少 Group 成员。动态生成、条件加载和脚本里的成员变化仍由实际运行场景决定。

## 扫描状态与完整性

扫描按批次推进，可以取消。目录遍历、场景读取和结果收集都有工作量预算；达到预算或遇到读取问题时，页面会保留已取得的结果并说明尚未完成的部分。

| 状态 | 含义 |
| --- | --- |
| `idle` | 尚未开始扫描。 |
| `scanning` | 扫描仍在进行，现有结果不完整。 |
| `complete` | 本次扫描范围已处理完成。 |
| `partial` | 读取问题或预算限制导致部分范围未能完成。 |
| `cancelled` | 用户取消了本次扫描，已有结果不代表完整范围。 |
| `failed` | 扫描请求无法完成，应先查看错误原因。 |

搜索与分页只筛选已经取得的声明，不会补扫遗漏场景。没有匹配项时，应结合扫描状态、范围和错误判断；`partial`、`cancelled` 或 `failed` 不能证明项目中不存在某个 Group。`complete` 也仅描述本次已保存场景的扫描范围，不包含运行时状态或随后发生的文件修改。

分批推进限制的是批次之间的工作量。单次 `ResourceLoader.load()` 不能中途抢占，读取一个较慢的场景时，取消要等该次加载返回后才能继续处理。

## API 入口

`GFSceneGroupIndex` 提供不依赖页面控件的索引入口，供制作期脚本使用：

- `begin_scan(root_path = "res://", options = {})` 开始一次扫描，返回 `Error`。
- `advance(entry_budget = 64)` 推进一批工作；返回 `true` 表示仍在扫描，返回 `false` 后应读取快照中的终态。
- `cancel()` 取消当前扫描。
- `get_snapshot()` 返回当前扫描状态、统计和诊断。
- `query(text = "", offset = 0, limit = 100)` 按组名、场景路径或节点路径筛选已收集的声明；`offset` 最小为 `0`，`limit` 限制在 `0` 到 `200`。结果包含 `rows`、匹配总数 `total` 和实际分页参数 `offset`、`limit`，每条 `rows` 包含 `group`、`scene_path`、`node_path`。

快照包含 `status`、`root_path`、已处理条目数 `entry_count`、尝试读取的场景数 `scene_count`、声明数 `row_count`、问题列表 `issues` 和未展开的问题数 `omitted_issue_count`。每条问题包含 `code`、`path`、`message`；完整性以 `status == "complete"` 判断，不能仅看问题列表是否为空。

`begin_scan()` 的 `options` 只接受下列预算键。超出范围或提供未知选项会拒绝请求，不会把无效预算解释为无限制：

| 选项 | 允许范围 |
| --- | --- |
| `max_depth` | `0` 到 `32` 层。 |
| `max_entries` | `1` 到 `100000` 个目录条目。 |
| `max_scenes` | `1` 到 `10000` 个场景。 |
| `max_rows` | `1` 到 `50000` 条声明。 |
| `max_scene_bytes` | `1` 到 `8388608` 字节，限制单个场景文件。 |

`GFSceneGroupDock` 提供 `refresh()`、`cancel_scan()` 和 `get_snapshot()`，用于工作区页面的扫描控制与状态读取。扫描完成后是否重新扫描，由使用者决定。

## 制作期边界

该工具只依赖 Kernel 编辑器基础能力，随完整 GF 插件挂载到工作区，不要求启用任何运行时扩展。索引读取 `PackedScene` 的保存状态，不实例化场景节点，不改写场景，也不自动修正或重命名 Group；索引不依赖 `.godot` 缓存。

读取场景仍经过 Godot 的资源加载流程，可能调用项目安装的自定义资源加载器；不实例化节点并不表示能够阻止加载器执行。应在受信项目中使用该工具，文件读取过程中发生的外部修改也不构成跨文件一致快照。

需要查询正在运行的场景树时，请使用 Godot 的 Group API 或已有运行时查询工具；游戏代码不应依赖 `gf.tool.scene_groups`。
