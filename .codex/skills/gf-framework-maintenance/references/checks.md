## By Change Type

- `addons/gf/**`: run focused tests when possible, run `check --check gdscript_warnings` for editor reload warning risk, then `check --suite full` before commit when behavior changed.
- Public API comments or signatures: run `python tools\generate_api_reference.py`, `python tools\generate_api_reference.py --check`, and `check --suite api`.
- Public API source or generated reference changes: run `public-api-boundary`; quick/full/release suites include it. It prevents planning route names from becoming public `class_name`, Catalog, or generated reference entries.
- Broad public API changes, removals, return type changes, or class moves: run `api-baseline-diff`. It compares the current generated API Catalog against the latest lower SemVer tag and reports added/removed classes, added/removed members, compatible/breaking signature changes, and extends changes. `release-status` reuses it and fails breaking changes unless the target release is a major bump.
- Public API comments or signatures in a dirty worktree: run `api-since-touched`; quick/full/release suites include it. It checks changed `public` / `protected` API doc blocks without failing untouched historical migration debt.
- Generated API docs: do not hand-edit `docs/api_catalog/**` or `docs/zh/reference/api/**`; regenerate with `tools/generate_api_reference.py`.
- Handwritten docs: run `check --suite docs`; use `public-docs-boundary` when docs mention optional extension defaults, editor workspace pages, AI maintenance paths, external research notes, package signature/security claims, or user-facing package/extension install prerequisites.
- Layer, extension dependency, manifest, preset, or contribution-boundary changes: run `dependency-boundary`, the full suite, and the specific maintenance tests for layer boundary and GDScript parse validation when relevant.
- Resource loading, resolver, cache, owner handle, or scene/UI async loading changes: run `resource-boundary` and `asset-lifecycle-boundary`; `resource-boundary` is report-only by default and lists direct `preload()` / `load()` / `ResourceLoader.*` path literals before strict resource-domain gates are enabled, while `asset-lifecycle-boundary` reports GFAssetHandle acquisitions that lack both owner and group anchors.
- Content package manifest, package dependency, resource-domain, or project profile changes: run `content-package-boundary`; quick/full/release suites include it. It scans tracked and untracked `gf_content_package.json` files and fails invalid JSON, unsupported package policy fields, missing/duplicate package IDs, missing/cyclic dependencies, and resources outside their package root.
- GF package manifests, modular package ownership, install package dependency graph, or package release boundary changes: run `package-boundary` and `package-closure-audit`; quick/full/release suites include both. `package-boundary` scans `packages/**/*.json`, rejects installer/download/checksum fields in local manifests, enforces package id/kind/version/path schema, checks dependency direction, dependency cycles, missing packages, and overlapping owned paths. `package-closure-audit` computes install closures and standard fan-in from the same manifests, warns on oversized extension closures and full debug dependencies, and fails runtime extension closures that pull in `gf.standard.editor`.
- GF package manifests, modular package ownership, cross-package `addons/gf` path literals, or cross-package `class_name` references: run `package-source-boundary`; quick/full/release suites include it. It scans package-owned source/config files and fails references to packages that are neither the same package nor direct declared dependencies.
- GF package builder, modular package zip output, offline bundle output, kernel package tool exclusion, runtime package external tool payload limits, registry archive fields, sha256, size, registry source manifest, unsupported package/source signature metadata, or release package metadata rules: run `package-build-boundary`; quick/full/release suites include it. It builds all non-preset packages into a temporary directory and validates every zip plus the generated registry index, registry source manifest, and offline bundle zip.
- User-facing package manager scripts, editor package manager dock, Godot native package CLI/backend, or no-Python install path changes: run `package-user-dependency-boundary`; quick/full/release suites include it. It scans `addons/gf/plugin.gd`, `addons/gf/kernel/package/**`, and `addons/gf/kernel/editor/package/**` and fails external process APIs, hard-coded Python/npm/Git/shell commands, or Python package tool path references.
- Package-owned runtime/editor source adding `OS.execute`, `OS.create_process`, `OS.shell_open`, or other external command dependencies: run `package-external-command-audit`; quick/full/release suites include it in report-only mode. Use `--fail-on-warnings` only after the current baseline is intentionally cleared or allowlisted.
- Root plugin entry, core-only install, or standard/editor contribution loading changes: run `core-only-smoke`; quick/full/release suites include it. It verifies `addons/gf/plugin.gd` can parse as gf-core without standard packages by rejecting parse-time standard `preload()` calls and direct references to standard `class_name` values.
- GF package installer, local archive extraction, staging, checksum/size validation, path ownership audit, runtime package external tool payload audit, target file copy, installed file list, lockfile write, or install rollback changes: run `package-install-smoke`; quick/full/release suites include it. It validates local archive install, dry-run, checksum failure no-mutation, path audit failure no-mutation, external tool payload failure no-mutation, and simulated copy failure rollback.
- GF package installer registry URL fetch, registry source channel/mirror selection, archive URL resolution, download cache, HTTP error handling, download size limits, remote checksum/size validation, remote runtime package external tool payload audit, unsupported registry package signature fields, mirror/retry policy, or network install rollback changes: run `network-install-smoke`; quick/full/release suites include it. It validates HTTP registry install, registry source mirror fallback, relative archive URL normalization, archive cache materialization, registry package signature rejection, external tool payload rejection, dry-run no project mutation, checksum/download failure no-mutation, and simulated copy failure rollback.
- GF preset manifests, generated preset registry entries, resolver preset dependency expansion, no-file preset lock entries, preset `required_by` pins, or preset uninstall pruning changes: run `preset-smoke`; quick/full/release suites include it. It validates that presets do not own archives or paths, preset installs copy only concrete package files, preset lock entries protect concrete packages, preset uninstall prunes unneeded dependencies, and manual pins survive.
- GF package manager status JSON, editor install wizard state, registry/lockfile package list rendering, preset install previews, source channel UI forwarding, source/channel/mirror diagnostic UI, install/uninstall dry-run JSON, checksum/install failure JSON, registry source integrity failure JSON, lockfile verify JSON, or uninstall risk summaries: run `package-manager-status-smoke` and `package-native-parity-smoke`; quick/full/release suites include both. For dock UI field, preset-first view, source/channel/mirror diagnostic, source/package signature rejection display, or wizard interaction changes, also run `package-editor-wizard-smoke`; quick/full/release suites include it. For Godot-native backend install/uninstall behavior, also run the focused GUT coverage in `tests/gf_core/kernel/package/test_gf_package_manager_backend.gd`. The status smoke validates empty project status, installed package dependency state, required_by blockers, project reference blockers, HTTP registry status caching, registry source signature rejection without project mutation, and registry package signature rejection without project mutation; the parity smoke verifies that Python maintenance status, registry source mirror fallback diagnostics, registry source signature rejection status, registry package signature rejection status, resolver verify-lock, install/uninstall dry-run result JSON, checksum failure behavior, registry source integrity failure behavior, and the Godot-native CLI agree on the shared registry/lockfile contract.
- GF package manifests, package split/ownership, focused GUT coverage ownership, or adding/removing package-level tests: run `package-focused-gut-mapping`; quick/full/release suites include it. The mapping is a maintenance policy in `tests/gf_core/package_focused_gut_mapping.json`, not part of the shipped package manifest schema.
- Godot native package CLI, no-Python user install path, CLI argument parsing, CLI human/JSON output, default release registry source, HTTP redirect/retry/backoff handling, registry source channel/mirror selection, source/channel/mirror diagnostics, unsupported registry package/source signature metadata, or `addons/gf/kernel/package/gf_package_manager_backend.gd` install/uninstall behavior changes: run `package-godot-cli-smoke`; quick/full/release suites include it. It validates Godot headless local and HTTP registry status/install paths, default release registry source install through redirect, default human-readable output, `--json` machine output, registry source mirror fallback, registry source diagnostics, remote archive cache materialization, transient HTTP retry/backoff, dry-run install, real install, lockfile verify, uninstall, and HTTP download failure no-mutation without invoking the Python installer on the user path.
- GF package manifests, installed package closure parseability, core-only/standard-only/extension/preset package Godot reload behavior, or package-level GDScript warning policy changes: run `package-godot-smoke`; use `package-godot-smoke --package <id>` to target newly split or adjusted packages, the full suite includes the representative mode, and the release suite runs `package_godot_matrix_smoke` for the generated registry's full package matrix. The all-package mode uses bounded parallel workers by default and can be tuned with `--jobs <n>`. It installs package closures into temporary Godot projects and fails on parse errors, script load errors, and GDScript reload warnings.
- GF package resolver, package installer uninstall transaction, `.gf/packages.lock.json`, dependency closure, manual/preset pin, `required_by`, uninstall protection, project reference scan, physical file delete, empty directory cleanup, or uninstall rollback changes: run `uninstall-smoke`; quick/full/release suites include it. It validates install-plan, verify-lock, shared dependency retention, manual pin retention, `.gf/` lockfile scan exclusion, project class-name reference blocking, physical uninstall, dry-run no-mutation, and simulated delete failure rollback.
- Project layout/profile changes: run `project-profile-boundary`; quick/full/release suites include it. Profiles are optional and project-owned, so GF provides the validator but does not require a fixed directory layout.
- Reference project changes: use `$gf-reference-boundary`.
- Release metadata: use `$gf-release-flow`; tag release CI must run `release-status --version <tag>` and `check --suite release`.

## Notes

`check --suite examples` is read-only unless `--sync-examples` is passed. Do not write-sync the external reference project by accident.

`check --check gdscript_warnings` opens the project editor headlessly and fails on GDScript reload warnings. It is meant to catch typed-Variant, unnecessary-await, and shadowing warnings that regular GUT runs can miss.

Use `@since unreleased` only for newly added public API whose release version is not final yet. `release-status --version <tag>` fails until every `@since` marker is a SemVer and no marker is newer than the release tag.

Use `api-baseline-diff --version <version> --enforce-version` before version decisions when the API surface changed substantially. Added classes are reported for release review. Removed classes, removed members, breaking or unknown signature changes, and extends changes are treated as breaking. Compatible signature changes such as adding defaulted tail parameters, widening parameter types to `Variant` or untyped, and appending enum values remain visible but do not force a major version bump.

`path-hygiene` scans both tracked files and untracked, non-ignored files. New files must not rely on `git diff --check` alone; `git diff --check` does not inspect untracked paths. It also checks that local workflow actions referenced as `./.github/actions/...` have an `action.yml`.

`api-since-touched` scans modified `addons/gf/**/*.gd` files. Untracked files are checked fully; tracked files are checked only where the current diff touches a `public` / `protected` API documentation block or its bound declaration. This keeps new API strict without turning historical untouched migration debt into a release blocker.

`dependency-boundary` statically scans bundled extension manifests, framework project defaults, and GF source boundaries. It fails on unsupported manifest fields, optional/soft dependency fields, default-enabled bundled extensions, non-empty `project.godot` `gf/extensions/enabled`, `kernel` or `standard` references to optional extension paths, IDs or classes, and cross-extension references inside bundled extensions.

`public-docs-boundary` scans public README, Asset Store text, Wiki entry pages, and handwritten `docs/zh` pages except generated API reference. It fails on AI-only maintenance paths, external package-manager research notes, planning track names, claims that optional extension pages or tools are fixed core workspace/editor features, premature GF package/registry signature verification claims, and public wording that makes Python/npm/npx/Git/Node/pip a prerequisite for ordinary GF package, extension, or preset installation.

`public-api-boundary` scans `addons/gf` source, API Catalog, and generated API Reference. It fails if internal planning route names appear as public API names or generated reference entries.

`resource-boundary` scans tracked and untracked, non-ignored `.gd` files outside vendored/local caches. It reports direct resource load literals and classifies script dependency loads as info, while `res://` / `uid://` runtime resource loads are warning-level debt. The command does not fail by default; use `--fail-on-issues` only after a project or release gate has an explicit allowlist/baseline.

`content-package-boundary` scans tracked and untracked, non-ignored `gf_content_package.json` manifests. It enforces the framework-level package contract: manifest and resource entry fields are whitelisted, package dependencies must resolve without cycles, and resource paths must stay inside the package root. It deliberately rejects installer/download/package-manager fields; those belong in project installers or external plugins, not GF content package manifests.

`asset-lifecycle-boundary` scans tracked and untracked runtime `.gd` files outside tests, vendored addons, and local caches. It reports `acquire_handle()`, `load_handle_async()`, and `request_entry_handle_async()` calls that omit both owner and group, because those handles depend on manual release and are common sources of long-lived cache pins. The command is report-only by default; use `--fail-on-warnings` only after a zero baseline is stable.

`project-profile-boundary` looks for `gf_project_profile.json`, `.gf/project_profile.json`, or `project_profile.json`, unless `--profile <path>` is passed. No profile means the check passes. The profile schema supports optional `zones` and `rules` with per-rule severity, roots, include/exclude globs, extension allow/deny lists, and path existence checks. This keeps GF flexible: projects opt into their own structure without turning any one layout into a framework requirement.

`package-boundary` scans tracked and untracked, non-ignored `packages/**/*.json` manifests. It enforces the local package contract for modular GF distribution: package manifests use whitelisted fields, local manifests do not contain remote archive/checksum/installer policy, dependency edges follow `kernel <- standard <- extension`, presets include concrete packages without owning paths, and package paths do not overlap. Remote registry fields belong in generated registry indexes, not source package manifests.

`package-closure-audit` computes every package install closure directly from `packages/**/*.json`, including preset roots, and reports per-kind closure counts plus standard fan-in. Warnings are report-only for now: extension closures above the configured thresholds, extensions that directly depend on the full `gf.standard.debug` package, and `gf.standard.debug` pulling UI into its closure. Runtime extension closures that include `gf.standard.editor` are errors because editor aggregation must not become runtime payload. Preset closures may be large, but the command records them so the editor wizard and CLI dry-run can keep full closure visibility.

`package-source-boundary` scans tracked and untracked package-owned source/config files under `addons/gf`. It resolves each `addons/gf` path literal and each GDScript `class_name` reference to the owning package, then fails if the source package did not declare that package as a direct dependency. The only built-in exceptions are narrow: `addons/gf/plugin.gd` may string-discover `gf_standard_editor_extensions.gd` for optional standard editor contributions, and kernel extension infrastructure may know the bundled extension root for manifest discovery.

`package-build-boundary` runs `tools/build_gf_package.py --all` in a temporary directory. It validates that every generated package zip has only `addons/` at the root, every entry stays under `addons/gf/`, generated/cache files are excluded, non-`gf.tool.*` runtime packages do not ship Python/npm/Node/shell tool payloads, `gf.kernel` does not ship `addons/gf/kernel/package_tools/` maintenance-side Python package manager scripts, the generated registry entry for each package matches the real archive sha256 and size, and the generated registry source channel pins the registry index sha256 and size. It also requests an offline bundle zip and verifies that the bundle contains exactly the generated registry/source/package zip files, uses safe relative paths, and that each registry archive reference resolves to a bundled package zip with matching sha256/size. Until Godot-native signature verification is implemented, the gate also rejects registry package entry and registry source signature fields so release assets cannot imply unverifiable trust. This is the local build prerequisite for later online install, offline bundle install, lockfile verification, and rollback-safe download flows. `release-status --version <tag>` adds the release-specific layer: it builds `gf-registry-<tag>.json` and `gf-registry-source.json` with release download URLs, then separately builds a versioned `gf-package-offline-bundle-<tag>.zip` with local relative registry/source/package zip references, and verifies package versions, archive asset names, sha256, size, source manifest integrity, and offline bundle local-path semantics before the tag workflow uploads assets.

`package-user-dependency-boundary` is the no-extra-dependency guard for user-facing package management. Maintenance-side Python tools may still live in `tools/` or the repository-local `addons/gf/kernel/package_tools/` mirror, but the root plugin, Godot package CLI/backend, and editor package manager dock must not execute external processes or reference those Python tool paths. The shipped `gf.kernel` package must also exclude that mirror, keeping ordinary install/uninstall dependent on Godot only.

`package-external-command-audit` scans package-owned `.gd` files under `addons/gf` and reports `OS.execute`, `OS.create_process`, and `OS.shell_open` calls by package id, API, command literal, and severity. It is report-only by default so known optional editor/debug integrations stay visible without blocking the current suite; pass `--fail-on-warnings` only when the baseline is ready to become a hard package policy.

`core-only-smoke` checks the root plugin entry for parse-time standard dependencies. It allows optional path-based discovery of standard editor contributions, but rejects direct `preload("res://addons/gf/standard/...")`, direct standard `load()` literals, and references to standard `class_name` values from `addons/gf/plugin.gd`.

`package-install-smoke` runs `tools/build_gf_package.py --all` into a temporary registry, then exercises `tools/gf_package_installer.py` against temporary project roots. It verifies installing `gf.extension.save` copies the resolved package closure into `addons/gf`, writes a lockfile with exact installed file lists that passes `verify-lock`, dry-run leaves the project untouched, checksum mismatch, external tool payloads, and archive path ownership failures do not mutate the target project, and a simulated copy failure rolls back package files without writing the lockfile.

`network-install-smoke` runs `tools/build_gf_package.py --all` into a temporary HTTP server root, then exercises `tools/gf_package_installer.py` through an HTTP registry URL and a registry source manifest. It verifies registry download, source channel mirror fallback when the primary registry is unavailable, source channel registry sha256/size validation, relative archive URL normalization, archive cache population, installing `gf.extension.save`, lockfile verification, registry package signature rejection without project mutation, remote external tool payload rejection without project mutation, dry-run without project mutation, checksum mismatch without project mutation, missing archive download failure without project mutation, and simulated copy failure rollback after downloads complete.

`preset-smoke` runs `tools/build_gf_package.py --all` into a temporary registry, then exercises `tools/gf_package_resolver.py` and `tools/gf_package_installer.py` with `gf.preset.*` roots. It verifies preset registry entries have no archive, sha256, size, or paths; installing a preset records a no-file preset lock entry; concrete packages are protected by `required_by`; preset uninstall removes the preset and prunes dependency-only packages; and manual pins remain installed.

`package-manager-status-smoke` runs `tools/build_gf_package.py --all`, then exercises `tools/gf_package_installer.py status` against temporary local and HTTP registries. It verifies that the status JSON lists registry packages, exposes preset install closures, shows installed package reason and `required_by` edges, reports required_by/project-reference uninstall blockers, uses the shared remote registry cache path, and rejects unsupported registry source or package signature fields without writing lockfiles or package files. This is the machine contract for future editor install wizard UI.

`package-native-parity-smoke` runs `tools/build_gf_package.py --all`, compares `tools/gf_package_installer.py status` with `addons/gf/kernel/package/gf_package_cli.gd status --json` on the same temporary registry, compares Godot direct offline bundle zip status with the Python maintenance status from the extracted bundled registry, compares registry source mirror fallback status and diagnostics from both implementations, compares registry source signature rejection status from both implementations, compares registry package signature rejection status from both implementations, compares `install gf.extension.save --dry-run --json` result snapshots from both implementations, compares checksum failure install snapshots plus no-mutation project state, compares registry source integrity failure install snapshots plus no-mutation project state, then repeats the status comparison after the Python maintenance installer writes a `gf.extension.save` lockfile fixture, compares `tools/gf_package_resolver.py verify-lock` with Godot CLI `verify --json`, and compares `uninstall gf.extension.save --dry-run --json` result snapshots from both implementations. It also runs matched corrupted-lockfile uninstall fixtures where `files` lists are removed from the Save closure and confirms both Python and Godot-native paths reject the uninstall without deleting package or user-added files. It compares package counters, installed ids, dependencies, preset packages, install previews, source mirror index and integrity diagnostics, source/package signature issue handling, dry-run install/uninstall order and mutation flags, checksum failure no-mutation behavior, registry source integrity failure no-mutation behavior, lockfile verify result, reason, required_by, uninstall blockers, offline bundle diagnostics, strict corrupted-lockfile rejection, and preserved files so the Python reference path and Godot-native user path cannot silently drift apart.

`package-editor-wizard-smoke` runs `tests/gf_core/kernel/editor/test_gf_package_manager_dock.gd` through headless Godot GUT, then builds a temporary registry, registry source manifest, offline bundle, and temporary projects containing only the built `gf.kernel` archive to drive the package manager Dock through Godot headless. It verifies that the editor package manager dock stays on the no-Python default source path, forwards registry source channels, renders source/channel/mirror/offline bundle diagnostics, rejects unsupported registry source and registry package signature fields at the Dock status layer without writing lockfiles or package files, opens in preset-first mode, can switch to raw extension and standard package views, renders install dependency closure plus uninstall blocker risk summaries, installs then uninstalls `gf.extension.save` plus standard dependencies from a local registry file, installs then uninstalls `gf.preset.rpg_save_dialogue` plus its concrete extension/standard closure from a local registry file, installs then uninstalls the same preset directly from an offline bundle zip, installs then uninstalls `gf.standard.storage` plus its `gf.standard.base` dependency from an HTTP registry, installs then uninstalls `gf.extension.save` plus standard dependencies from an HTTP registry, and installs then uninstalls the RPG preset through the minimal project's own Dock/backend without adding Python package tools. The minimal-project helper scripts live under `.gf/` so they do not trip the project reference blocker that real user scripts should trigger. The command reads explicit Godot log files and fails on script load errors, parse errors, or GDScript reload warnings. Python is still used by the maintenance command to build the temporary registry/offline bundle, host the local HTTP fixture, prepare the minimal-kernel fixtures, and launch Godot; the package operation itself goes through the Godot-native editor backend.

`package-focused-gut-mapping` validates `tests/gf_core/package_focused_gut_mapping.json` against `packages/**/*.json`. Every non-preset package must map to at least one focused GUT script; preset packages must not map because they own no source. Test paths must exist, stay under `res://tests/gf_core/`, and match the package test scope, with a narrow exception for `gf.standard.editor` integration coverage under `res://tests/gf_core/kernel/editor/`.

`package-godot-cli-smoke` runs `tools/build_gf_package.py --all`, then exercises `addons/gf/kernel/package/gf_package_cli.gd` through Godot headless. It verifies status on an empty project through `--json`, the default human-readable status output, local dry-run install without mutation, local real `gf.extension.save` install, `verify` on the written lockfile, safe uninstall, HTTP registry install with remote archive caching, a temporary project containing only the built `gf.kernel` archive installing `gf.extension.save` from a local registry through its own CLI, verifying the lockfile, uninstalling the extension closure, verifying again, and keeping kernel files while pruning unused standard files, another minimal-kernel project installing `gf.preset.rpg_save_dialogue` from a local registry through its own CLI, verifying, uninstalling the preset closure, verifying again, and pruning the concrete preset packages back to kernel-only, another minimal-kernel project installing the same preset directly from an offline bundle zip to prove the user-side offline path, another minimal-kernel project installing `gf.extension.save` from an HTTP registry through its own CLI, verifying, uninstalling the extension closure, verifying again, and keeping kernel files while pruning unused standard files, another minimal-kernel project installing `gf.standard.storage` through its own CLI, verifying, uninstalling the standard package closure, verifying again, and pruning the project back to kernel-only, another minimal-kernel project installing `gf.preset.rpg_save_dialogue` through its own CLI, verifying, uninstalling the preset closure, verifying again, and pruning the concrete preset packages back to kernel-only, transient HTTP 500 retry/backoff for registry and archive downloads, HTTP source channel mirror fallback with `registry_mirror_index=0`, source/channel/mirror/registry integrity/offline bundle diagnostics, default release registry source install with `--registry` omitted and an HTTP redirect in front of the source manifest, HTTP dry-run without project mutation, remote runtime package external tool payload rejection without project mutation, and missing HTTP archive failure without project mutation. Signature metadata in registry package entries or registry source manifests must fail until Godot-native verification exists; it must never be silently ignored by the user path. Python is still used by the maintenance command to build the temporary registry/offline bundle, host the local HTTP fixture, prepare the minimal-kernel fixture, and launch Godot, but the package operation itself goes through the Godot-native backend.

`package-godot-smoke` runs `tools/build_gf_package.py --all`, installs package roots into temporary Godot projects, writes a temporary preload script for installed `addons/gf/**/*.gd`, enables the GF root plugin in `project.godot`, and opens the project with headless Godot editor. The default mode covers representative roots: `gf.kernel`, `gf.standard.storage`, `gf.extension.save`, and `gf.preset.rpg_save_dialogue`; `package-godot-smoke --package <id>` derives one or more selected scenarios from the generated registry for focused package-split verification; `package-godot-smoke --all-packages` derives scenarios from the generated registry and covers every package entry, including presets. All-package mode defaults to `jobs=4`, keeps each package closure in its own temporary project, and merges scenario output back in package order; use `--jobs <n>` when a slower machine needs less parallelism. `package_godot_matrix_smoke` is the release-suite wrapper for that full matrix. The check fails on script loading/parse errors or GDScript reload warnings. Exit leak warnings are recorded in scenario details as cleanup debt under the same policy as other Godot checks.

`uninstall-smoke` runs `tools/build_gf_package.py --all` into a temporary registry, then exercises both `tools/gf_package_resolver.py` and `tools/gf_package_installer.py` against temporary project roots. It verifies that installing `gf.extension.save` resolves required standard packages, lockfiles verify against the registry, uninstalling one extension preserves standard packages still required by another extension, manually pinned standard packages survive dependent extension removal, and project scripts referencing a package class block uninstall. It also verifies physical uninstall deletes only package-owned files, keeps shared or manually pinned package files, leaves dry-run projects untouched, and rolls back deleted files when a simulated delete failure occurs. The project reference scanner intentionally excludes `.gf/` so the lockfile itself does not count as user code.

GUT output is not allowed to mask Godot script errors or reload warnings. If Godot reports `SCRIPT ERROR`, parse errors, or GDScript reload warnings, the maintenance check fails even when the GUT summary says all tests passed.

Godot ObjectDB, resource still in use, and RID allocation leak warnings are recorded in check output as cleanup debt. They are not CI-failing yet; after the leak baseline is cleaned, promote them to hard fail. For verbose log triage, run `python tools\gf_maintenance.py godot-exit-leak-report --log <stdout.log> --log <stderr.log> --json`; use `--fail-on-leaks` only when the baseline is ready to become a gate.

The GitHub PR / push CI should stay equivalent to `check --suite full`; release workflow should stay equivalent to `release-status --version <tag>` plus `check --suite release`. The tag workflow must upload the Asset Store zip, `gf-registry-<tag>.json`, `gf-registry-source.json`, `gf-package-offline-bundle-<tag>.zip`, and every non-preset modular package zip generated by `tools/build_gf_package.py --all --version <tag>`. If CI must be weakened temporarily, record the reason in the maintenance notes before merging.
