# GF Check Matrix

Start with `python tools\gf_maintenance.py workspace-status --json`. It categorizes dirty files and recommends checks. In a dirty long-running workspace, use repeated `--path <file>` arguments to get a check plan for the current turn's files instead of all historical local changes.

## By Change Type

- `addons/gf/**`: run focused tests when possible, run `check --check gdscript_warnings` and the standalone LSP check for early warning diagnosis, then `check --suite full` before commit. Full and release suites always include the strict LSP error-and-warning gate.
- Public API comments or signatures: run `python tools\generate_api_reference.py`, `python tools\generate_api_reference.py --check`, and `check --suite api`.
- Public API source or generated reference changes: run `public-api-boundary`; quick/full/release suites include it. It prevents planning route names from becoming public `class_name`, Catalog, or generated reference entries.
- Broad public API changes, removals, return type changes, or class moves: run `api-baseline-diff`. It compares the current generated API Catalog against the latest lower SemVer tag and reports added/removed classes, added/removed members, compatible/breaking signature changes, and extends changes. `release-status` reuses it and fails breaking changes unless the target release is a major bump, or the maintainer explicitly approves and records a minor/patch compatibility break before running `release-status --allow-breaking-api`.
- Public API comments or signatures in a dirty worktree: run `api-since-touched`; quick/full/release suites include it. It checks changed `public` / `protected` API doc blocks without failing untouched historical migration debt.
- Generated API docs: do not hand-edit `docs/api_catalog/**` or `docs/zh/reference/api/**`; regenerate with `tools/generate_api_reference.py`. The generator stages Catalog and Reference together and replaces both only after successful validation; changes to this path require rollback/escape-root self-tests.
- Handwritten docs: run `check --suite docs`; use `public-docs-boundary` when docs mention optional extension defaults, editor workspace pages, AI maintenance paths, external research notes, package signature/security claims, or user-facing package/extension install prerequisites.
- Layer, extension dependency, manifest, preset, or contribution-boundary changes: run `dependency-boundary`, the full suite, and the specific maintenance tests for layer boundary and GDScript parse validation when relevant.
- Resource loading, resolver, cache, owner handle, or scene/UI async loading changes: run `resource-boundary` and `asset-lifecycle-boundary`; `resource-boundary` is report-only by default and lists direct `preload()` / `load()` / `ResourceLoader.*` path literals before strict resource-domain gates are enabled, while `asset-lifecycle-boundary` reports GFAssetHandle acquisitions that lack both owner and group anchors.
- Content package manifest, package dependency, resource-domain, or project profile changes: run `content-package-boundary`; quick/full/release suites include it. It scans tracked and untracked `gf_content_package.json` files and fails invalid JSON, unsupported package policy fields, missing/duplicate package IDs, missing/cyclic dependencies, and resources outside their package root.
- GF package manifests, modular package ownership, install package dependency graph, or package release boundary changes: run `package-boundary` and `package-closure-audit`; quick/full/release suites include both. `package-boundary` scans `packages/**/*.json`, rejects installer/download/checksum fields in local manifests, enforces package id/kind/version/path schema, checks dependency direction, dependency cycles, missing packages, and overlapping owned paths. `package-closure-audit` computes install closures and standard fan-in from the same manifests, warns on oversized extension closures and full debug dependencies, and fails runtime extension closures that pull in `gf.standard.editor`.
- GF package manifests, modular package ownership, cross-package `addons/gf` path literals, or cross-package `class_name` references: run `package-source-boundary`; quick/full/release suites include it. It requires every distributable file under `addons/gf` to have a non-preset package owner, explicitly ignores generated `.import` sidecars, and scans source/config references to fail undeclared package dependencies.
- GF package builder, modular package zip output, offline bundle output, kernel package tool exclusion, runtime package external tool payload limits, registry schema, framework compatibility bounds, registry archive fields, sha256, size, registry source manifest, unsupported package/source signature metadata, or release package metadata rules: run `package-build-boundary`; package/full/release suites include it. Inside a suite it validates a private copy of that invocation's sealed artifact set; when run standalone it builds and seals all non-preset packages first. Both modes validate every zip plus the registry index, registry source manifest, and offline bundle zip.
- User-facing package manager scripts, editor package manager dock, Godot native package CLI/backend, or no-Python install path changes: run `package-user-dependency-boundary`; quick/full/release suites include it. It scans `addons/gf/plugin.gd`, `addons/gf/kernel/package/**`, and `addons/gf/kernel/editor/package/**` and fails external process APIs, hard-coded Python/npm/Git/shell commands, or Python package tool path references.
- Package-owned runtime/editor source adding `OS.execute`, `OS.create_process`, `OS.shell_open`, or other external command dependencies: run `package-external-command-audit`; quick/package/full/release suites run it with `--fail-on-warnings`. Direct command runs remain report-only by default for investigation, but suite runs are strict and allow only declared editor jump exceptions.
- Root plugin entry, core-only install, or standard/editor contribution loading changes: run `core-only-smoke`; quick/full/release suites include it. It verifies `addons/gf/plugin.gd` can parse as gf-core without standard packages by rejecting parse-time standard `preload()` calls and direct references to standard `class_name` values.
- Local package transaction, target framework compatibility, archive extraction, path ownership, preset pin/prune, status/preview JSON, install/update/verify/uninstall, project reference protection, exact file lists, dry-run, rollback, journal/recovery, shared dependency, or manual pin changes: run `package-godot-cli-smoke --profile local` and the focused native backend GUT. The Godot CLI/backend/transaction engine is the only project-mutating implementation; the Python resolver stays plan-only.
- Registry/source/channel fetch, archive URL resolution, HTTP redirect/retry/backoff, mirror selection, content-addressed cache, download limits, checksum/size validation, unsupported signature fields, remote payload audit, or network failure rollback changes: run `package-godot-cli-smoke --profile network`.
- Preset manifests, generated preset registry entries, resolver preset expansion, no-file preset lock entries, preset `required_by` pins, or preset uninstall pruning changes: run `package-godot-cli-smoke --profile local`.
- Package manager status JSON, shared CLI arguments/output, install/uninstall dry-run, verify, checksum/install failure, source integrity failure, or uninstall risk summaries: run both local and network profiles. For Dock fields, preset-first views, diagnostics, signature rejection display, or wizard interaction, also run `package-editor-wizard-smoke`.
- GF package manifests, package split/ownership, focused GUT coverage ownership, or adding/removing package-level tests: run `package-focused-gut-mapping`; quick/package/full/release suites include it. The mapping is a maintenance policy in `tests/gf_core/package_focused_gut_mapping.json`, not part of the shipped package manifest schema.
- Godot native package CLI, no-Python user install path, shared CLI parsing/output, or backend transaction behavior changes: run both local and network profiles. For local-only transaction changes, run local; for HTTP-only changes, run network. The aggregate `package-cli` suite remains a local convenience, while CI uses independent `package-cli-local` and `package-cli-network` shards.
- GF package manifests, installed package closure parseability, core-only/standard-only/extension/preset package Godot reload behavior, or package-level GDScript warning policy changes: run `package-godot-smoke`; use `package-godot-smoke --package <id>` to target newly split or adjusted packages, the full suite includes the representative mode, and the release suite runs `package_godot_matrix_smoke` for the generated registry's full package matrix. The all-package mode uses bounded parallel workers by default and can be tuned with `--jobs <n>`. It installs package closures into temporary Godot projects and fails on parse errors, script load errors, and GDScript reload warnings.
- GF package resolver, `.gf/packages.lock.json`, dependency closure, manual/preset pin, `required_by`, uninstall protection, project reference scan, physical delete, empty-directory cleanup, or uninstall rollback changes: run the local CLI profile and focused native backend GUT. Resolver plan commands must never persist installed state.
- Project layout/profile changes: run `project-profile-boundary`; quick/full/release suites include it. Profiles are optional and project-owned, so GF provides the validator but does not require a fixed directory layout.
- Reference project changes: use `$gf-reference-boundary`.
- Release metadata: use `$gf-release-flow`; build the immutable artifact set once, validate it with `release-status --artifact-manifest`, and keep tag CI set-equivalent to the release suite.

## Notes

`check --suite examples` is read-only unless `--sync-examples` is passed. Do not write-sync the external reference project by accident.

`check --suite quick` is the sub-30-second development loop and deliberately excludes `maintenance-self-test`. When maintenance Python, CI, release workflow, or this check matrix changes, run `maintenance-self-test` explicitly; `framework` and `full` also retain it.

`check --check gdscript_warnings` opens the project editor headlessly and fails on GDScript reload warnings. It is meant to catch typed-Variant, unnecessary-await, and shadowing warnings that regular GUT runs can miss.

All maintenance-owned Godot commands resolve through `tools/gf_godot_process.py` and run under the shared process supervisor. On Windows this bypasses the detached Steam `godot.exe` launcher when its foreground tools executable is available. Set `GF_GODOT_EXECUTABLE` only when an explicit executable override is required.

`check --check gdscript_lsp_diagnostics` imports the project, then connects to the active editor LSP or spawns a temporary headless LSP when none is available. The full and release suites, Ready/main's `framework-lsp` shard, and the release framework shard run it unconditionally and fail on errors, warnings, diagnostic timeouts, connection failures, or transport failures.

`check --suite full` defaults to three isolated workers; explicit `--jobs 2` through `--jobs 6` tune the bounded parallelism. Workspaces are materialized, run, validated, and cleaned with their private OS roots in batches no larger than `jobs`. Before shards start, two real same-name Godot probe projects must prove that platform data/config/cache paths and `user://` stay inside separate private roots; unsupported or self-contained layouts fail closed. On Windows, clone, materialization staging, and private temporary paths must also fit the projected short-path budget. If the automatic local root is unavailable, `GF_MAINTENANCE_VALIDATION_TEMP_ROOT` may point to an existing short local fixed-volume parent; the runner validates its direct volume identity and creates a random identity-pinned child, while relative, missing, source-owned, linked/reparse, UNC, device, mapped, and substituted roots are rejected. Untracked regular files are captured from stable handles in deadline-aware 1 MiB chunks, with hard limits of 64 MiB per file and 256 MiB in total. The absolute suite deadline covers capture, artifact preparation, artifact tree scans/hashing/copying, the probe, shard execution, and final revalidation. Each shard runs inside a retained POSIX process group or Windows Job Object that is force-cleared before the report is trusted. The parent also rejects duplicate/non-finite JSON, oversized or unexpected report fields, workspace escapes, linked/replaced report or log directory chains, schema drift, shard-coverage mismatches, source-fingerprint changes, unowned failure logs, and package reports whose manifest digest or artifact count differs from the suite's sealed set. Use `--jobs 1` only to diagnose concurrency, resource contention, or order-sensitive failures; it preserves the complete check set and does not weaken the LSP gate.

Ready PRs and `main` runs are the only events allowed to emit the exact `GF repository policy` and `GF merge gate` required contexts. A manual run on another ref uses a non-required policy name and skips the Full-equivalent matrices, so it cannot substitute for PR validation.

Within one suite invocation, package smoke checks share one sealed package artifact set containing the package archives, registry index, registry source manifest, and offline bundle. The runner validates both the source-workspace fingerprint and every file hash before giving each consumer a private copy. Consumers cannot modify the shared bytes, and the set is never cached or reused across source revisions. Standalone package smoke commands build and seal their own invocation-scoped set.

`project-settings-drift` fails when `project.godot` has staged or unstaged local changes. Use it after tests or headless editor checks when `ProjectSettings` writes may have leaked transient test state into the project file. Do not use it to block intentional project metadata edits; instead, review and commit those edits deliberately.

Use `@since unreleased` only for newly added public API whose release version is not final yet. `release-status --version <tag>` fails until every `@since` marker is a SemVer and no marker is newer than the release tag.

Use `api-baseline-diff --version <version> --enforce-version` before version decisions when the API surface changed substantially. Added classes are reported for release review. Removed classes, removed members, breaking or unknown signature changes, and extends changes are treated as breaking. Compatible signature changes such as adding defaulted tail parameters, widening parameter types to `Variant` or untyped, and appending enum values remain visible but do not force a major version bump.

`path-hygiene` scans both tracked files and untracked, non-ignored files. New files must not rely on `git diff --check` alone; `git diff --check` does not inspect untracked paths. It also checks that local workflow actions referenced as `./.github/actions/...` have an `action.yml`.

`api-since-touched` scans modified `addons/gf/**/*.gd` files. Untracked files are checked fully; tracked files are checked only where the current diff touches a `public` / `protected` API documentation block or its bound declaration. This keeps new API strict without turning historical untouched migration debt into a release blocker.

`dependency-boundary` statically scans bundled extension manifests, framework project defaults, and GF source boundaries. It fails on unsupported manifest fields, optional/soft dependency fields, default-enabled bundled extensions, non-empty `project.godot` `gf/extensions/enabled`, `kernel` or `standard` references to optional extension paths, IDs or classes, and cross-extension references inside bundled extensions.

`public-docs-boundary` scans public README, Asset Store text, Wiki entry pages, and handwritten `docs/zh` pages except generated API reference. It fails on AI-only maintenance paths, external package-manager research notes, planning track names, claims that optional extension pages or tools are fixed core workspace/editor features, premature GF package/registry signature verification claims, and public wording that makes Python/npm/npx/Git/Node/pip a prerequisite for ordinary GF package, extension, or preset installation.

`public-api-boundary` scans `addons/gf` source, API Catalog, and generated API Reference. It fails if internal planning route names appear as public API names or generated reference entries.

`resource-boundary` scans tracked and untracked, non-ignored `.gd` files outside vendored/local caches. It reports direct resource load literals and classifies script dependency loads as info, while `res://` / `uid://` runtime resource loads are warning-level debt. The command does not fail by default; use `--fail-on-issues` only after a project or release gate has an explicit allowlist/baseline.

`content-package-boundary` scans tracked and untracked, non-ignored `gf_content_package.json` manifests. It enforces the framework-level package contract: manifest and resource entry fields are whitelisted, package dependencies must resolve without cycles, and resource paths must stay inside the package root. It deliberately rejects installer/download/package-manager fields; those belong in project installers or external plugins, not GF content package manifests.

`asset-lifecycle-boundary` scans tracked and untracked runtime `.gd` files outside tests, vendored addons, and local caches. It reports `acquire_handle()`, `load_handle_async()`, and `request_entry_handle_async()` calls that omit both owner and group, because those handles depend on manual release and are common sources of long-lived cache pins. The command is report-only by default; use `--fail-on-warnings` only after a zero baseline is stable.

`project-profile-boundary` looks for `gf_project_profile.json`, `.gf/project_profile.json`, or `project_profile.json`, unless `--profile <path>` is passed. No profile means the check passes. The profile schema supports optional `zones` and `rules` with per-rule severity, roots, include/exclude globs, extension allow/deny lists, path existence checks, naming conventions, feature module contracts, generated-file boundaries, and bucket-size limits. This keeps GF flexible: projects opt into their own structure without turning any one layout into a framework requirement.

`package-boundary` scans tracked and untracked, non-ignored `packages/**/*.json` manifests. It enforces the local package contract for modular GF distribution: package manifests use whitelisted fields, local manifests do not contain remote archive/checksum/installer policy, dependency edges follow `kernel <- standard <- extension`, presets include concrete packages without owning paths, and package paths do not overlap. Remote registry fields belong in generated registry indexes, not source package manifests.

`package-closure-audit` computes every package install closure directly from `packages/**/*.json`, including preset roots, and reports per-kind closure counts plus standard fan-in. Warnings are report-only for now: extension closures above the configured thresholds, extensions that directly depend on the full `gf.standard.debug` package, and `gf.standard.debug` pulling UI into its closure. Runtime extension closures that include `gf.standard.editor` are errors because editor aggregation must not become runtime payload. Preset closures may be large, but the command records them so the editor wizard and CLI dry-run can keep full closure visibility.

`package-source-boundary` first scans all tracked and untracked distributable files under `addons/gf` and requires package ownership even for Markdown, images, and other non-source payloads; Godot-generated `.import` sidecars are the explicit exception. It then resolves each `addons/gf` path literal and each GDScript `class_name` reference in source/config files to the owning package, failing undeclared direct dependencies. The only built-in reference exceptions are narrow: `addons/gf/plugin.gd` may string-discover `gf_standard_editor_extensions.gd` for optional standard editor contributions, and kernel extension infrastructure may know the bundled extension root for manifest discovery.

`package-build-boundary` validates the suite's sealed package artifact set, or builds and seals one invocation-scoped set when run standalone. It verifies that every package zip has only `addons/` at the root, every entry stays under `addons/gf/`, generated/cache files are excluded, runtime packages do not ship external tool payloads, registry compatibility bounds are present, and every registry/source/offline-bundle reference matches the real archive bytes. Until Godot-native signature verification exists, package and source signature fields remain fail-closed. Release preparation uses `tools/build_gf_release_artifacts.py` to build every package archive once and derive the online registry, source manifest, offline bundle, Asset Store zip, and SHA-256 artifact manifest from one immutable set. `release-status --artifact-manifest <path>` validates those existing bytes without rebuilding them.

`package-user-dependency-boundary` is the no-extra-dependency guard for user-facing package management. Pure maintenance-side builders, resolvers, and cache helpers may live in `tools/`, but no Python installer or second transaction engine is allowed. The root plugin, Godot package CLI/backend, and editor package manager dock must not execute external processes or reference Python package tool paths; ordinary install/update/uninstall remains Godot-only.

`package-external-command-audit` scans package-owned `.gd` files under `addons/gf` and reports `OS.execute`, `OS.create_process`, and `OS.shell_open` calls by package id, API, command literal, and severity. Direct command runs are report-only by default for investigation. `check --suite quick`, `check --suite package`, `check --suite full`, and `check --suite release` pass `--fail-on-warnings`, so newly introduced package-owned external command calls fail unless they match an explicit allowlist entry.

`core-only-smoke` checks the root plugin entry for parse-time standard dependencies. It allows optional path-based discovery of standard editor contributions, but rejects direct `preload("res://addons/gf/standard/...")`, direct standard `load()` literals, and references to standard `class_name` values from `addons/gf/plugin.gd`.

`package-godot-cli-smoke --profile local` consumes a revalidated private copy of the suite's sealed registry/offline bundle, or builds and seals an invocation-scoped set when run standalone, then drives only the Godot-native CLI/backend/transaction engine. It covers local status, human/JSON output, dry-run, install, update-all, verify, uninstall, preset pin/prune, compatibility rejection, exact file lists, offline bundle use, rollback, and no-mutation failures. Journal/recovery, project-reference blocking, shared dependencies, and manual pins remain focused native backend GUT responsibilities.

`package-godot-cli-smoke --profile network` hosts temporary HTTP fixtures and covers registry/source/channel loading, redirects, mirrors, retry/backoff, relative archive URLs, content-addressed cache, download budgets, integrity checks, fail-closed signature metadata, remote payload rejection, and network failure no-mutation/rollback. The aggregate command runs both profiles for local use; CI keeps them independent so one slow network matrix does not consume the local matrix budget.

`package-editor-wizard-smoke` runs `tests/gf_core/kernel/editor/test_gf_package_manager_dock.gd` through headless Godot GUT, then consumes a revalidated private copy of the suite's sealed registry, registry source manifest, offline bundle, and `gf.kernel` archive; standalone use builds and seals that set first. It prepares temporary projects to drive the package manager Dock through Godot headless. It verifies that the editor package manager dock stays on the no-Python default source path, forwards registry source channels, renders source/channel/mirror/offline bundle diagnostics, rejects unsupported registry source and registry package signature fields at the Dock status layer without writing lockfiles or package files, opens in preset-first mode, can switch to raw extension and standard package views, renders install dependency closure plus uninstall blocker risk summaries, installs then uninstalls `gf.extension.save` plus standard dependencies from a local registry file, installs then uninstalls `gf.preset.rpg_save_dialogue` plus its concrete extension/standard closure from a local registry file, installs then uninstalls the same preset directly from an offline bundle zip, installs then uninstalls `gf.standard.storage` plus its `gf.standard.base` dependency from an HTTP registry, installs then uninstalls `gf.extension.save` plus standard dependencies from an HTTP registry, and installs then uninstalls the RPG preset through the minimal project's own Dock/backend without adding Python package tools. The minimal-project helper scripts live under `.gf/` so they do not trip the project reference blocker that real user scripts should trigger. The command reads explicit Godot log files and fails on script load errors, parse errors, or GDScript reload warnings. Python is still used by the maintenance command to prepare fixtures, host the local HTTP fixture, and launch Godot; the package operation itself goes through the Godot-native editor backend.

`package-focused-gut-mapping` validates `tests/gf_core/package_focused_gut_mapping.json` against `packages/**/*.json`. Every non-preset package must map to at least one focused GUT script; preset packages must not map because they own no source. Test paths must exist, stay under `res://tests/gf_core/`, and match the package test scope, with a narrow exception for `gf.standard.editor` integration coverage under `res://tests/gf_core/kernel/editor/`.

The measured local and network profiles have independent 1200-second policy budgets; the aggregate command retains a 2400-second budget. Each Godot subprocess remains capped at 120 seconds and ordinary checks retain the 600-second default. `check --timeout N` raises the minimum per-check budget but cannot shorten a dedicated policy. Use `--suite-timeout N` only for an intentional overall deadline.

`package-godot-smoke` consumes a revalidated private copy of the suite's sealed package set, or runs `tools/build_gf_package.py --all` once and seals the result when invoked standalone. It installs package roots into temporary Godot projects, writes a temporary preload script for installed `addons/gf/**/*.gd`, enables the GF root plugin in `project.godot`, and opens the project with headless Godot editor. The default mode covers representative roots: `gf.kernel`, `gf.standard.storage`, `gf.extension.save`, and `gf.preset.rpg_save_dialogue`; `package-godot-smoke --package <id>` derives one or more selected scenarios from the sealed registry for focused package-split verification; `package-godot-smoke --all-packages` derives scenarios from that registry and covers every package entry, including presets. All-package mode defaults to `jobs=4`, keeps each package closure in its own temporary project, and merges scenario output back in package order; use `--jobs <n>` when a slower machine needs less parallelism. `package_godot_matrix_smoke` is the release-suite wrapper for that full matrix. The check fails on script loading/parse errors or GDScript reload warnings. Exit leak warnings are recorded in scenario details as cleanup debt under the same policy as other Godot checks.

GUT output is not allowed to mask Godot script errors or reload warnings. If Godot reports `SCRIPT ERROR`, parse errors, or GDScript reload warnings, the maintenance check fails even when the GUT summary says all tests passed.

Godot ObjectDB, resource still in use, and RID allocation leak warnings are recorded in check output as cleanup debt. They are not CI-failing yet; after the leak baseline is cleaned, promote them to hard fail. Successful maintenance commands remove logs created or rewritten by that invocation; failed or interrupted invocations retain their current evidence while historical logs are bounded to 7 days, 32 files, and 16 MiB. `ai_analysis/godot_logs/` is the only repository-local diagnostic log root. Top-level `.gf/*.log` files are legacy transient output and are removed on successful maintenance runs without traversing `.gf` package state. For verbose log triage, produce the source log with `--keep-logs` (or `GF_MAINTENANCE_KEEP_LOGS=1`), then run `python tools\gf_maintenance.py godot-exit-leak-report --log <stdout.log> --log <stderr.log> --json`; use `--fail-on-leaks` only when the baseline is ready to become a gate. Run `log-hygiene --all --json` after the evidence is no longer needed; use `log-hygiene --dry-run --json` to inspect candidates first.

The GitHub Ready PR / push CI must stay set-equivalent to `check --suite full`; its required shards are `framework-gut`, `framework-lsp`, `framework-static`, `package-contract`, `package-editor`, `package-cli-local`, `package-cli-network`, and `package-godot-ci`. A focused `windows-process-supervision` job also runs `maintenance-self-test` on `windows-latest` and must feed the merge gate so native Job Object cleanup remains covered. Branch protection requires both `GF repository policy` and the aggregate `GF merge gate`, so a title/body-only metadata edit can rerun policy without cancelling validation already running for the same source SHA while still failing closed. Draft PRs instead use repository policy plus the pure-Python quick suite behind an independent `GF draft gate`; changing the PR base reruns the applicable Draft or Ready gate. Release uses its release-equivalent framework and package shards, replaces `package-godot-ci` with `package-godot-release`, builds the complete artifact set exactly once, validates it with `release-status --artifact-manifest`, and publishes those same bytes only after every required job succeeds. If CI must be weakened temporarily, record the reason before merging.
